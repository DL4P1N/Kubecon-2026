## Synthetic seed and private demo-pass session

From the repo root, with dependencies installed:

```sh
npx tsx scripts/seed-demo.mts --dry-run
# Load ES_URL, ES_USERNAME=companion_svc, ES_PASSWORD privately from the app's
# environment; NODE_EXTRA_CA_CERTS must trust the ES CA. Do not paste secrets.
# Use the same EMBEDDINGS_PROVIDER/EMBEDDING_DIMS/ES_INFERENCE_ID as the app.
npx tsx scripts/seed-demo.mts
```

The live command requires HTTPS with normal CA validation and the
`companion_svc` account. It writes the same 12 synthetic attendees and 12
entitlements through the production ES client on every run; it creates no
indices, changes no mappings, and deletes no data. Names start with
`SYNTHETIC DEMO`; security=6, observability=6, kubernetes=12 before other
attendees join. Both consent flags are true for these explicitly synthetic
fixtures. Expiry is 24 hours from the seed run. Embeddings are generated by the
configured provider (two distinct interest sets); do not silently substitute
local hashes for the deployed model. One fixture starts with no allowed rooms.
The script prints counts only, never IDs or tokens. Rerunning resets the
synthetic passes and refreshes their expiry.

For the revocation demonstration, create a private session for the fixed
synthetic allowed pass. Load the app's `TOKEN_SIGNING_KEY` privately as well:

```sh
npx tsx scripts/seed-demo.mts --session-file /tmp/cc-demo-session.json
```

The file must be outside the checkout; it is created exclusively with mode
0600; its session token expires after 15 minutes. An existing file is refused. Remove only
that known temporary file before creating a fresh rehearsal session.
On this Mac, copy its token without displaying it:

```sh
node -e 'process.stdout.write(JSON.parse(require("fs").readFileSync("/tmp/cc-demo-session.json","utf8")).token)' | pbcopy
```

On Windows PowerShell, use an absolute private path under `$env:TEMP` for the
session file, then copy without displaying it:

```powershell
(Get-Content -Raw "$env:TEMP\cc-demo-session.json" | ConvertFrom-Json).token | Set-Clipboard
```

Before recording, rehearse the following setup in the demo-pass tab's DevTools
console. Run
`sessionStorage.setItem("cc.token", prompt("Paste private synthetic session token"))`,
paste the clipboard value, close DevTools, and reload `/schedule`. A new tab
has its own session storage; install it in the intended tab. Clear the
clipboard and remove the private file after rehearsal. Never put the token in
slides, board posts, terminal output, source control, or trace attributes.

To revoke only that synthetic pass while leaving the already-issued QR valid:

```sh
npx tsx scripts/seed-demo.mts --revoke
# Restore after the deny has been shown:
npx tsx scripts/seed-demo.mts --restore
```

The command accepts no arbitrary attendee ID and refuses a pass that lacks its
synthetic marker. It preserves the pass expiry. Use this demo-pass tab for
revocation; it does not revoke the fresh attendee from the live registration
step. Expired tokens and revoked entitlements are separate checks.
